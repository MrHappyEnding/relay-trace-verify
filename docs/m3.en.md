# M3: Two-agent handoff and paired branches

[![中文](assets/lang-zh.svg)](m3.md) [![English](assets/lang-en.svg)](m3.en.md)

2026-10-09: **M3 passes acceptance within the local trusted-development-task scope**: 48 zero-cost
protocol checks, 14 real-model checks and a bilingual read-only viewer. The second scaffold is
mini-swe-agent 2.4.6 with `gpt-5.4-mini-2026-03-17`. Native Codex continuation and three cross-framework
context handoffs all complete the same fixed task.

## Implemented behavior

| Operation | Identity | Restored state |
| --- | --- | --- |
| Recovery | Same Trial / Attempt, new Execution / epoch | Last committed stage, not process memory |
| Handoff | Same Trial, new Attempt / Execution / epoch | Workspace and explicitly chosen context |
| Fork | New Experiment and independent Trials / Attempts / Executions | One sealed checkpoint, no shared writable branch directories |

`--staged --pause-after-checkpoint` stops the source sandbox after stage one, commits its checkpoint
and enters `sealed` without starting stage two. Handoffs progress through
`requested → prepared → completed`. Preparation validates the task, image and bundle and persists a
hashed context package; a database transaction then transfers execution authority. Prepared means
**local inputs and configuration are validated**. The target sandbox starts after transfer; provider
availability is not pre-validated. Preparation failure returns the source Trial to sealed. A lost
activation acknowledgement converges by checking the committed record. Cancellation shares the
transaction boundary; old Attempts cannot publish through the new epoch.

Handoff and Experiment request keys are idempotent; conflicting configurations fail. Checkpoint
references protect source artifacts. Cancellation retains audit material; explicit target retirement
releases its references. Nested forks and mini native-session resume are disabled. Branches and
handoff targets have zero automatic recovery allowance.

## Context and verification boundaries

| Branch | Policy | Target-visible material |
| --- | --- | --- |
| A-continue | native | Same-version/model Codex native session and workspace |
| B-workspace | task-only | Original task and workspace; no source summary or trajectory |
| B-summary | summary | Workspace plus source final statement, labeled unverified self-report |
| B-trajectory | optional portable | Codex → Harbor ATIF → text projection of messages, tool calls and observations |

Portable context is quoted prompt material, **not target-native tool-history import**. It drops source
reasoning fields, metrics and native runtime state and declares these losses. Summaries cap at 6,000
characters with a truncation flag. Projections exceeding 24 KB are rejected instead of silently losing
tool pairs. Mini carries its own Responses reasoning state between requests; that is separate from
the source Codex projection.

RTV freezes each completed branch workspace and starts a fresh verifier sandbox. It imports only the
declared workspace, compares digests, disables networking and runs fixed task tests. Source logs,
sessions and credentials are absent; hidden verifier output is absent from handoff context. This is
still a trusted development-task system, not a security-hardened evaluation service for hostile code.

## Zero-cost example

Start local Docker, PostgreSQL and Temporal as described in [M1](m1.en.md), then install the current
optional dependencies:

```bash
uv sync --python 3.13 --locked --group runtime --dev
uv run --no-sync rtv runtime init
uv run --no-sync rtv runtime prepare
```

Run `uv run --no-sync rtv runtime worker` in one terminal. In another:

```bash
uv run --no-sync rtv runtime submit --key m3-source --staged \
  --pause-after-checkpoint --ttl 900
uv run --no-sync rtv runtime status <trial_id>
# After reaching sealed:
uv run --no-sync rtv runtime fork <trial_id> --key m3-paired \
  --adapter mini-fixture --portable --ttl 300
uv run --no-sync rtv runtime experiment <experiment_id>
uv run --no-sync rtv runtime serve --port 8765
```

Open the [local viewer](http://127.0.0.1:8765). Its Chinese / English buttons switch language. It is
read-only, binds to loopback and refreshes every three seconds, showing checkpoint lineage, branch
results, handoff/execution events, usage and cleanup. `mini-fixture` runs the real DefaultAgent loop
and Harbor tools with three fixed provider responses; it does not exercise model reasoning.
A separate example can use `handoff <trial_id> --key relay-1 --adapter mini-fixture --context summary`
for a same-Trial relay.

Defaults are `work/runtime-v3`, PostgreSQL schema `rtv3`, queue `rtv-m3-<root-hash>` and Workflow IDs
`rtv3-<trial_id>`. M1/M2 records and histories remain intact, **without automatic migration**. Stop
old workers and active tasks before upgrading. Set the same `RTV_RUNTIME_ROOT` for all commands and
the viewer to select an isolated root. Services, fixed tasks and images are reused; this is not
multi-host resource isolation.

## Accounting and paid-validation budget

Model HTTP calls run on the host; the API key never enters the sandbox or Workflow. Mini reuses the
upstream loop, templates, action parser and observation formatting. RTV supplies the Harbor
Environment bridge and Responses Model bridge, rather than Harbor's MiniSwe adapter. Codex continues
through the existing Harbor integration.

- Each mini HTTP request has prior database admission. SDK retries are disabled; timeout is 45 seconds.
- Each branch allows at most eight requests. Text/tool input JSON is capped at 40,000 UTF-8 bytes;
  output is capped at 4,096 tokens. Reserve $0.062 per request against a $0.50 branch budget.
- Reservations are never reused, including failed or UNKNOWN calls. Settle observed usage before
  parsing tools. A lost response becomes UNKNOWN and stops without retry. Persist only exception class, HTTP status, allowlisted codes/parameters and request ID, never raw response bodies.
  Cancellation cannot retract an in-flight request but blocks subsequent requests and tools.
- Estimate costs at the fixed model rates: $0.75/M input, $0.075/M cached input, $4.50/M output.
  Cached input is a subset of input, not additional tokens. See the
  [official model pricing](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
- These are conservative reservations for a pinned transport, not a mathematical provider-invoice
  guarantee or a universal hard spending limit. Codex still has wall-clock control and observed usage;
  subscription tokens have no dollar conversion.

One real acceptance run uses **two Codex subscription stages** (source and native continuation) plus
**three paid mini branches**. At most 24 API requests reserve $1.488 in total. Expected API spend is
**$0.20–$1** per run was the initial estimate. The owner subsequently approved a **cumulative $8**
for this M3 debugging session, including earlier attempts; it is a ceiling, not a spending target.
Both model and scaffold change, so results cannot isolate a scaffold effect.

Run only after owner approval and credential configuration. Keep the key in an ignored local file
with permissions 600; never put its value in commands, chat or Git. The script does not automatically
repeat paid runs:

```bash
uv run --no-sync python scripts/m3_model_smoke.py \
  --output work/m3-real-1 --auth-file "$HOME/.codex/auth.json" \
  --api-key-file work/openai-api-key.txt \
  --allow-model-calls --allow-api-calls --approved-budget-usd 8 \
  --prior-reserved-usd 1.612 --api-call-limit 8
```

This reproduces the fourth run's allowance: $1.612 reserved in three earlier runs plus at most
$1.488 for this run, totaling $3.10. Reconcile all prior ledgers and update the carryover before
another run; do not reuse this historical value. The script rejects nonfinite/nonpositive budgets
and prior reservations plus the new maximum above approval. Reports include request counts,
UNKNOWN requests, reservations and cumulative occupancy. This is manually reconciled session
accounting, not an organization-wide budget service.

Each branch references shared prefix operation IDs rather than copying counters. Policy end-to-end
cost is prefix plus incremental cost. Physical experiment cost counts the source prefix once. UNKNOWN
is not zero; observed API costs remain separately visible. Summing all four end-to-end totals would
overcount physical spend.

## Transport defect exposed by real requests

SDK output materializes absent `reasoning.status` and `function_call.namespace` as `null`, while input schemas require omission. Projection now recursively omits null fields while retaining non-null `phase`, encrypted reasoning and tool/result pairs. The fix passes offline input validation of three real trajectories, regression tests and multistep provider execution in attempt three.

Attempt three exposed a completion-protocol defect: RTV matched literal `echo` command text,
missing `cd /workspace && echo ...`. The bridge now executes through Harbor and checks the first
output line and exit code, adapting [mini-swe-agent 2.4.6's output protocol](https://github.com/SWE-agent/mini-swe-agent/blob/v2.4.6/src/minisweagent/environments/local.py).
Contract tests compare upstream behavior for leading whitespace, submission bodies, nonzero exits
and markers after other output. A mocked transport test confirms wrapped submission stops the loop
without another model call.
