2026-10-09：代码、零费用协议验收与本地页面完成；**真实双 agent 验收尚未运行**。
第二种执行框架固定为 mini-swe-agent 2.4.6，API 模型配置为
`gpt-5.4-mini-2026-03-17`。此前 M2 的真实 Codex 证据不能替代 M3 跨框架证据。

## 当前实现

| 操作 | 身份与状态 | 能恢复什么 |
| --- | --- | --- |
| Recovery | 同 Trial / Attempt，新 Execution / epoch | 最近已提交的阶段；不恢复进程内存 |
| Handoff | 同 Trial，新 Attempt / Execution / epoch | 工作区与显式选择的上下文 |
| Fork | 新 Experiment、独立 Trial / Attempt / Execution | 同一已封存检查点，分支间无共享可写目录 |

源任务使用 `--staged --pause-after-checkpoint`，阶段一完成后停止沙箱、提交检查点并进入
`sealed`，不自动执行第二阶段。交接记录依次经过 `requested → prepared → completed`；
准备阶段验证任务 / 镜像 / bundle，持久化有哈希的上下文包，再由数据库事务迁移控制权。
这里的 prepared 指**本地输入与配置已验证**，目标沙箱在迁移之后创建，尚不保证目标
provider 可用。准备失败时源 Trial 回到 sealed；已提交但确认丢失时查询记录收敛。
取消与迁移使用同一事务边界；旧 Attempt 的发布被 epoch 拒绝。

Handoff / Experiment 的调用键保证幂等，改变同一个键的配置会报错。源检查点由引用
保护，取消不会自动删除审计材料；目标 Trial 显式 retire 后才释放相应引用。当前不支持
嵌套分叉或 mini 原生会话恢复；分支与交接目标的自动恢复额度固定为 0。

## 上下文和验证边界

| 分支 | 策略 | 目标可见内容 |
| --- | --- | --- |
| A-continue | native | 同版本 / 同模型的原生 Codex 会话与工作区 |
| B-workspace | task-only | 原任务与工作区，不含源摘要 / 轨迹 |
| B-summary | summary | 工作区与源 agent 最后陈述，明确标记为未经验证的自述 |
| B-trajectory | portable，可选 | Codex → Harbor ATIF → 文本投影，包含消息、工具调用和观测 |

portable 是目标 prompt 中的引用资料，**不是目标原生工具历史导入**。转换丢失源 reasoning
字段、指标、原生运行状态；上下文包记录损失。摘要至多 6,000 字符并标记截断；投影最多
24 KB，超出时拒绝，避免默默丢失工具配对。mini 的本轮 API 自身 reasoning 状态由
Responses 输出继续携带，与源 Codex 的 portable 投影不同。

分支完成后，RTV 冻结工作区并创建独立 verifier 沙箱，仅导入声明的工作区，核对 digest，
禁用网络，执行固定 task 的测试。验证器不接收源日志、会话或凭据；隐藏验证输出不进入
交接包。范围仍是仓库内可信开发任务，尚非面向恶意提交的安全评测服务。

## 运行零费用示例

先按 [M1](m1.md) 启动本机 Docker、PostgreSQL 与 Temporal。使用当前可选依赖：

```bash
uv sync --python 3.13 --locked --group runtime --dev
uv run --no-sync rtv runtime init
uv run --no-sync rtv runtime prepare
```

一个终端启动 `uv run --no-sync rtv runtime worker`；另一个终端执行：

```bash
uv run --no-sync rtv runtime submit --key m3-source --staged \
  --pause-after-checkpoint --ttl 900
uv run --no-sync rtv runtime status <trial_id>
# 等待 sealed 后：
uv run --no-sync rtv runtime fork <trial_id> --key m3-paired \
  --adapter mini-fixture --portable --ttl 300
uv run --no-sync rtv runtime experiment <experiment_id>
uv run --no-sync rtv runtime serve --port 8765
```

浏览 [本地页面](http://127.0.0.1:8765)，使用中文 / English 按钮切换。页面只读、只监听
loopback，每 3 秒刷新，展示共同检查点、分支结果、交接 / 执行事件、用量和清理状态。
`mini-fixture` 使用真实 DefaultAgent 循环和 Harbor 工具，但 provider 是三个固定响应，
不代表真实模型推理。另一个独立示例可用 `handoff <trial_id> --key relay-1
--adapter mini-fixture --context summary` 创建同 Trial 的接力。

当前默认目录 `work/runtime-v3`，数据库 schema `rtv3`，队列 `rtv-m3-<root-hash>`，
Workflow ID `rtv3-<trial_id>`。M1 / M2 数据和历史保留，**不自动迁移**；升级前结束旧
worker / 活动任务。可用 `RTV_RUNTIME_ROOT` 选择隔离目录，各命令和 viewer 必须使用同一值。
本机服务、镜像和固定 task 继续复用；配置不是多主机资源隔离方案。

## 用量与付费验收预算

模型网络请求在宿主进程发出，API key 不传入沙箱或 Workflow。mini 复用上游执行循环、
模板、工具解析及观测格式，RTV 实现 Harbor Environment 桥和 Responses Model 桥；没有
直接使用 Harbor 的 MiniSwe adapter。Codex 仍由原 Harbor 集成执行。

- mini 每请求先在数据库记 admission，再发 HTTP；SDK 重试关闭，45 秒超时。
- 每分支最多 8 次请求，输入 JSON 的文本 / 工具包最多 40,000 UTF-8 bytes，输出上限
  4,096 tokens；每请求预留 $0.062，每分支预留预算 $0.50。
- 已知、失败或 UNKNOWN 请求的预留都不回收复用。响应到达后先结算用量，再解析工具；
  响应丢失则 UNKNOWN 并停止，不自动重试。取消不能撤回已发送请求，但阻止后续请求 / 工具。
- 费用按固定模型价格估算，缓存输入是总输入的子集，不重复累计。价格为每百万 input
  $0.75、cached input $0.075、output $4.50，见 [模型价格](https://developers.openai.com/api/docs/models/gpt-5.4-mini)。
- 这是固定传输配置的保守预留，并非 provider 账单的数学保证或所有 agent 的通用硬金额
  上限。Codex 仍只支持 wall clock 和事后用量；订阅 tokens 不折算美元。

一次真实验收包括 **2 次 Codex 订阅阶段**（源阶段 + A 原生继续）和 **3 个付费 mini 分支**，
最多 24 个 API 请求，累计预留最多 $1.488。预估实际 API 花费 **$0.20–$1**，建议批准
**$2** 预算；owner 已批准本次 $2，等待 API key 后执行。两种 scaffold 与模型同时变化，不可将差异单独归因于框架。

仅在 owner 确认费用并配置凭据后运行以下脚本；不要把 key 写进命令、聊天或 Git。将 key
保存在已忽略且权限为 600 的本地文件。脚本不执行付费自动重跑：

```bash
uv run --no-sync python scripts/m3_model_smoke.py \
  --output work/m3-real-1 --auth-file "$HOME/.codex/auth.json" \
  --api-key-file work/openai-api-key.txt \
  --allow-model-calls --allow-api-calls --approved-budget-usd 2
```

分支账本引用共享前缀的 operation IDs，不复制计数。每策略全程成本 = 前缀 + 分支增量；
物理实验总成本只计算一次源前缀。UNKNOWN 不当作零，已观测费用单独展示。不要把四个
“全程成本”直接相加当成实验支出。
