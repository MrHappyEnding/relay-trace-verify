# M0：Harbor 接入与容器恢复原型

[![中文](assets/lang-zh.svg)](m0.md) [![English](assets/lang-en.svg)](m0.en.md)

状态：准备与模拟协议测试完成，实际容器及真实 agent 验证待完成。更新：2026-10-08。

## 已准备的入口

在仓库根目录使用 Python 3.12+：

```bash
uv sync --python 3.13 --locked --group harbor --dev
uv run --no-sync rtv harbor-doctor
```

基础 RTV 仍支持 Python 3.11；可选 `harbor` 依赖组固定到 0.24.0，由 uv.lock
锁定传递依赖。执行普通 `uv sync` 可能移除可选组，再运行集成前需重新包含该组。
`harbor-doctor` 只检查版本、Harbor 任务 schema、Docker Linux daemon 和 Compose，
不启动容器、不下载镜像、不调用模型。条件不满足时输出 JSON 并以非零状态退出。

Docker 就绪后运行：

```bash
uv run --no-sync rtv harbor-smoke --output work/m0-smoke-1
```

首次运行会下载 Dockerfile 中固定 digest 的 Python 基础镜像，并创建两个短时 CPU
任务环境。Harbor 的网络控制会附加 sidecar 容器并构建其镜像；所有容器镜像 ID
写入报告，sidecar 的上游基础镜像尚未固定 digest。仅支持仓库内
`examples/tasks/positive-sum` 这一可信 fixture；从其他工作目录
运行时用 `--task` 指定其路径。输出目录必须不存在。容器不接 GPU、不注入模型凭据，
运行网络策略为 `no-network`。构建拉取基础镜像需要网络。

## 协议与验证

1. Harbor `Task` 加载任务，`DockerEnvironment` 创建源环境。
2. 受控脚本完成正数过滤，但故意保留空输入错误。
3. 通过当前运行专属 Compose project 和 `main` service 找到源任务容器，停止并确认已停止，再导出 `/workspace`。
4. RTV 提交本地文件检查点，并校验后恢复到新的主机目录。
5. 在同一镜像的新 Harbor 容器中恢复文件，回传比较路径、文件内容和权限摘要。
6. Harbor `Verifier` 必须先判定部分解失败，再判定目标脚本完成的解通过。
7. 检查源容器文件未受目标修改影响；删除本次创建的环境，核对是否仍有容器残留。

停止整个源容器是本次文件导出的静止边界，会丢弃进程内存。它不证明任意真实
agent 能够在阶段边界保存其原生会话。Harbor 0.24.0 的 `stop(delete=False)`
会走 Compose down，不能用它假设“保留停止后的容器供导出”；因此此原型在导出前
使用 Docker stop，最终再调用 Harbor 清理。

## 产物

- `report.json`：依赖与任务 digest、镜像 ID、源 / 目标身份、检查点、验证和清理状态。
- `events.jsonl`：本地控制事件，关联 checkpoint 与执行身份。
- `exported/`、`restored/`、`roundtrip/`：导出与往返校验所用文件。
- `checkpoints/`：文件快照；`source/` 和 `target/`：Harbor 日志。

报告模式为 `harbor-scripted-smoke`，`model_calls` 为 0。这是传输与验证原型；
没有会话、ATIF、预算账本、持久化恢复或模型接力效果。Verifier 在目标容器内运行，
不是独立隐藏测试服务。清理失败会使报告失败，并保留对应 session 名；不做全局 prune。
构建缓存镜像可能保留；本次不删除其他项目的镜像或容器。

可选择跑实际容器集成测试：

```bash
RTV_RUN_DOCKER=1 uv run --no-sync pytest -m integration -q
```

普通测试默认跳过它；跳过不计为容器验证成功。先运行 `harbor-doctor`，Docker
不可用时不要反复启动 smoke。下一步是完成实际往返，再接第一个真实 agent；
使用付费模型前遵守[费用约定](learning-plan.md)。
